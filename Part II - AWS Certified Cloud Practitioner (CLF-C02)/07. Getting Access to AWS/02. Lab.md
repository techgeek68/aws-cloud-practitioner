# Chapter 7 Lab: Getting Access to AWS


# 7.6 Lab: Create a Key Pair in the Console

**What a key pair is.** 

A key pair consists of a public key that AWS stores and a private key that you download. Linux instances use it for SSH authentication. Windows instances use it to decrypt the Administrator password for RDP access.

---
**Prerequisites**

- An AWS account with permission to manage EC2 resources.

- A web browser.

---
### 7.6.1 Procedure

1. Sign in to the AWS Management Console.

2. Check the Region selector at the top right and select the Region you intend to work in. Key pairs are Region-specific.

3. Type `EC2` in the console search bar and select **EC2**.

4. In the left navigation pane, scroll to the **Network & Security** section.

5. Choose **Key Pairs**.

6. Choose **Create key pair** at the top right.

7. In **Name**, enter a descriptive name, for example `MyLabKey`.

8. Under **Key pair type**, choose one:

   - **RSA** works with both Linux and Windows instances. AWS generates 2048-bit SSH-2 RSA keys.

   - **ED25519** offers stronger security and better performance but is supported for Linux instances only. Do not choose it if you intend to connect to Windows.

9. Under **Private key file format**, choose one:

   - **.pem** for OpenSSH clients on Linux, macOS, and Windows 10 or 11 with built-in OpenSSH.

   - **.ppk** for PuTTY on Windows.

10. Optionally add tags to help with organization and cost allocation.

11. Choose **Create key pair**.

![Creating Key Pairs](<images/Creating Key Pairs.png>)
---
12. Note that the private key file downloads automatically. This is the only time it is available.

13. Move the downloaded file out of the Downloads folder to a secure location.

14. Restrict the file permissions before use.

- On Linux or macOS:
      ```sh
      chmod 400 /path/to/MyLabKey.pem
      ```
   - Verify with `ls -l MyLabKey.pem`.

![Manaing Permissions of Key Pairs](<images/Managing Key Pairs.png>)
---
- On Windows PowerShell, first remove inherited permissions:
      ```powershell
      icacls.exe "C:\path\to\MyLabKey.pem" /inheritance:r
      ```
   - Then grant read access to the current user only:
      ```powershell
      icacls.exe "C:\path\to\MyLabKey.pem" /grant:r "$($env:USERNAME):R"
      ```
   - Verify with `Get-Acl MyLabKey.pem`.

15. Confirm the new key pair now appears in the **Key Pairs** list.

---
> AWS does not retain your private key. If the file is lost it cannot be recovered, and you will need to create a new key pair and replace it on any instance that used it.
---
### 7.6.2 Recommendations

- Keep the private key private. Never commit it to source control and never share it.

- Keep a backup in an encrypted location such as a password manager or an encrypted drive.

- Name keys so the project, environment, and owner are obvious, for example `prod-web-david`.

- Use RSA for anything that may involve Windows instances.

- For PuTTY, use the `.ppk` file directly, or convert a `.pem` file with PuTTYgen.

### 7.6.3 Cleanup

1. Open **EC2**, then **Key Pairs**.

2. Select the key pair.

3. Choose **Actions**, then **Delete**.

4. Type the confirmation text and confirm.

5. Delete the local private key file if it is no longer needed.

# 7.7 Lab: Create a Security Group in the Console

**What a security group is.** A security group is a set of rules controlling inbound and outbound traffic for AWS resources, most commonly EC2 instances. It is stateful, meaning a reply to an allowed inbound request is automatically permitted outbound. Each security group belongs to one VPC and can only be used within that VPC. Security groups are compared with network ACLs in section 9.5.

**Prerequisites**

- An AWS account with permission to manage EC2 resources.

- A web browser.

### 7.7.1 Procedure

1. Sign in to the AWS Management Console.

2. Confirm the Region selector shows the Region you intend to work in.

3. Type `EC2` in the console search bar and select **EC2**.

4. In the left navigation pane, scroll to the **Network & Security** section.

5. Choose **Security Groups**.

6. Choose **Create security group** at the top right.

7. In **Security group name**, enter a clear name, for example `MyLabSG`. The name and description cannot be changed after creation.

8. In **Description**, state the purpose, for example `Allow SSH and HTTP access for lab`.

9. In **VPC**, select the VPC this security group will belong to. If you have not created one, select the `default VPC`.

10. Under **Inbound rules**, choose **Add rule**.

11. Set **Type** to `SSH`. The protocol and port 22 fill in automatically.

12. Set **Source** to **My IP**. Never use `0.0.0.0/0` for SSH or RDP.

13. Choose **Add rule** again.

14. Set **Type** to `HTTP`. The protocol and port 80 fill in automatically.

15. Set **Source** to `0.0.0.0/0` for public web traffic. If the VPC is IPv6 enabled, add a second HTTP rule with source `::/0`.

16. Review the **Outbound rules** section. New security groups include a default rule allowing all outbound traffic. Leave it in place unless the workload requires egress filtering.

17. Optionally add tags.

18. Check the name, description, VPC, and every rule before continuing.

![Security Group Creation Review](<images/Security Group Creation Review.png>)
---
19. Choose **Create security group**.

20. Confirm the new security group appears in the list with the expected VPC and rule count.

![Confriming Security Group](<images/Confirm Security Group .png>)

---
### 7.7.2 Attaching the Security Group to an Instance

For a new instance:

1. In the launch instance wizard, open the **Network settings** section.

2. Choose **Select existing security group**.

3. Select the security group.

For an existing instance:

1. Open **EC2**, then **Instances**.

2. Select the instance.

3. Choose **Actions**, then **Security**, then **Change security groups**.

4. Add or remove security groups.

5. Choose **Save**.

---
### 7.7.3 Recommendations

- Restrict SSH and RDP to a specific source address. Opening them to the world is the most common cause of compromised instances.

- Open only the ports the application actually needs.

- Choose names that reflect role and environment, since they cannot be renamed.

- Add `::/0` alongside `0.0.0.0/0` for public rules when the VPC is IPv6 enabled, or IPv6 clients will fail silently.

- Review security groups periodically and remove rules that are no longer needed.

---
### 7.7.4 Cleanup

1. Detach the security group from any instance still using it. A security group in use cannot be deleted.

2. Open **EC2**, then **Security Groups**.

3. Select the security group.

4. Choose **Actions**, then **Delete security groups**.

5. Confirm the deletion.

# 7.8 Lab: Launch an EC2 Instance in the Console

This completes the sequence: you created a key pair in section 7.6 and a security group in section 7.7, and this lab uses both to launch and connect to an instance.

> Note: AWS rebuilt the launch wizard as a single page. All configuration sections appear together, and the summary panel on the right replaces the old "Review and Launch" step.

### 7.8.1 Step 1: Open the EC2 Console

1. Sign in to the AWS Management Console as the IAM user created in section 7.4.

2. Enter your MFA code if prompted.

3. Confirm the Region selector at the top right shows the Region you intend to use. Resources are Region specific, and an instance launched in the wrong Region will not appear in your usual view.

4. Type `EC2` in the search bar and select **EC2**.

5. Confirm the Region indicator again on the EC2 dashboard.

![Confirming Regions](<images/Confirming Regions.png>)
---
### 7.8.2 Step 2: Name and Tag the Instance

1. Choose **Launch instance**.

2. In **Name and tags**, enter `My Web Server`. This creates a tag with key `Name`.

3. Choose **Add additional tags**.

4. Add a tag with key `Environment` and value `Dev`.

### 7.8.3 Step 3: Choose the AMI

An Amazon Machine Image is the template defining the operating system and preinstalled software the instance boots from.

1. Under **Application and OS Images**, search for `Red Hat`, or choose Amazon Linux, Ubuntu, or Windows Server.

2. Confirm the architecture is **64-bit (x86)** unless you intend to use Arm.

### 7.8.4 Step 4: Choose the Instance Type

The instance type determines vCPU count, memory, and network capacity.

1. Review the listed types and their specifications.

2. Select a free tier eligible type, normally `t3.micro`, or `t2.micro` in Regions where `t3.micro` is unavailable. Free tier eligibility depends on when your account was created, per section 7.2.

![Instace Family](<images/Instance Type.png>)
---
### 7.8.5 Step 5: Select the Key Pair

1. Under **Key pair (login)**, select the key pair created in section 7.6.

2. If creating a new one instead, enter a name, choose `.pem` for OpenSSH on Linux, macOS, or Windows 10 and 11, or `.ppk` for PuTTY, then choose **Create key pair**.

3. Store the downloaded file securely. It cannot be downloaded again.

---
### 7.8.6 Step 6: Configure Network Settings

1. Next to **Network settings**, choose **Edit**.

2. Select a **VPC**. The default VPC is appropriate here.

3. Select a **Subnet**, which determines the Availability Zone.

4. Set **Auto-assign public IP** to **Enable**, so the instance is reachable from the internet.

5. Under **Firewall (security groups)**, choose **Select existing security group** and select the group created in section 7.7.

6. Confirm the inbound rules match the operating system: **SSH** on TCP 22 for Linux, or **RDP** on TCP 3389 for Windows, each with source **My IP**. Add **HTTP** on port 80 only if you intend to serve web traffic.

![Network Setting](<images/Network Setting.png>)
---
7. Optionally attach an **IAM instance profile** under **Advanced details** if the instance needs to call AWS services, per section 8.5.

8. Leave **Detailed CloudWatch monitoring** disabled unless you need one-minute metrics, since it carries an additional charge.

Always restrict SSH and RDP to **My IP** rather than `0.0.0.0/0`. Both ports are continuously scanned and are the most common route to a compromised instance.

### 7.8.7 Step 7: Configure Storage

1. Review the root volume the wizard prefilled from the AMI, normally 8 GiB `gp3`.

2. Increase the size if needed. The free tier includes up to 30 GB of EBS storage.

3. To add a second volume, choose **Add new volume** and set its type, size, and encryption.

### 7.8.8 Step 8: Launch

1. Review the **Summary** panel on the right, confirming AMI, instance type, key pair, security group, and storage.

2. Choose **Launch instance**.

3. Choose **View all instances**.

4. Wait until **Instance state** shows **Running**.

5. Wait until **Status checks** shows **3/3 checks passed** before attempting to connect.

![Inatnce Lauched and 3/3 Check Pass](<images/Instance lauched.png>)
---
### 7.8.9 Step 9: Connect to a Linux Instance

1. Select the running instance in the **Instances** list.

2. Choose **Connect** at the top of the page.

3. Open the **SSH client** tab, which shows the exact command for this instance.

![Finding SSH Client](<images/Connect SSH Client.png>)
---
4. Set permissions on the private key file.

- Linux or macOS:
     ```bash
     chmod 400 /path/to/your-key.pem
     ```

   - Verify with `ls -l your-key.pem`.

- Windows PowerShell:
     ```powershell
     icacls.exe "C:\path\to\your-key.pem" /inheritance:r
     icacls.exe "C:\path\to\your-key.pem" /grant:r "$($env:USERNAME):R"
     ```
   - Verify with `Get-Acl your-key.pem`

5. Connect, substituting the default user for your AMI.
   ```bash
   ssh -i /path/to/your-key.pem ec2-user@<Public-IPv4-address>
   ```
6. Type `yes` at the host authenticity prompt.

7. Confirm you reach a shell prompt.

![Connected shell session on the instance](<images/Connected shell session on the instance.png>)

### 7.8.10 Step 10: Connect to a Windows Instance (Windows Server)

1. Select the running Windows instance.

2. Choose **Connect**, then the **RDP client** tab.

3. Choose **Get password**.

4. Upload the `.pem` private key file.

5. Choose **Decrypt password** and note the Administrator password.

6. Download the **Remote Desktop File** and open it, or enter the public IP in your RDP client manually.

7. Sign in with username `Administrator` and the decrypted password.

8. Accept the certificate warning.

---
> Windows 10 and 11 include Remote Desktop Connection. On macOS, use Microsoft Remote Desktop from the App Store.
---
### 7.8.11 Cleanup

1. Open **EC2**, then **Instances**.

2. Select the instance, choose **Instance state**, then **Terminate instance**, and confirm.

![Terminating Instance](<images/Terminating Instance.png>)
---
3. Choose **Volumes** and delete any volume that was not removed with the instance.

4. Choose **Elastic IPs** and release any address that is no longer associated.

5. Choose **Snapshots** and delete any snapshot you created.

An instance accrues charges while running, even when idle. **Stop** pauses compute charges while storage continues to bill; **Terminate** removes the instance entirely.

---
> A better alternative to SSH and RDP:

>Both require an open inbound port. AWS Systems Manager Session Manager provides shell access with no inbound rules, no key pair, and full session logging, and is covered in section 35.2.

## 7.9 Lab Cost Discipline

Every lab in this course creates billable resources. Two habits prevent the bill that ends most people's AWS study.

**Set one budget alert now, before the first lab.**

1. Open the Billing and Cost Management console.

2. Choose **Budgets**, then **Create budget**.

3. Choose **Cost budget**.

4. Set the period to **Monthly** and enter a small budgeted amount, for example 5 USD.

5. Add an alert threshold at 80% of the budgeted amount.

6. Enter the email address that should receive the alert.

7. Create the budget.

The full billing toolset, including Cost Explorer, cost allocation tags, and Cost Anomaly Detection, is covered in Chapter 15.

---
## Tear down every lab when you finish it.

- Follow the cleanup section at the end of each lab. Every lab in this course has one.

- Check the EC2 console for running instances, unattached EBS volumes, and unassociated Elastic IP addresses.

- Check for NAT gateways, which are the most expensive thing a beginner leaves running by accident.

- Work in one Region. Resources abandoned in a Region you have forgotten about will keep billing quietly.
